# Salon App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A phone-first salon web app: 3D hairstyle preview, live camera try-on, service catalog, account or guest entry, queue tokens with a 15-minute alert, and NFC/QR reviews.

**Architecture:** One npm package. `server/` is an Express 5 API over a SQLite file, built by a `createApp(db, opts)` factory so tests run against an in-memory database. `src/` is a Vite + React client that talks to `/api` and renders the 3D head with three.js primitives. In production Express serves the built client.

**Tech Stack:** Node 24 (runs `.ts` directly, built-in `node:sqlite`), Express 5, Vite, React, TypeScript, react-router-dom, three, @mediapipe/tasks-vision, qrcode, Vitest, supertest, @testing-library/react, jsdom.

**Spec:** `docs/superpowers/specs/2026-11-25-salon-app-design.md`

## Global Constraints

- Node >= 24. No native-compiled dependencies (use `node:sqlite`, not better-sqlite3).
- Server files are TypeScript run by Node's type stripping: relative imports carry the `.ts` extension; no enums, no parameter properties, no namespaces.
- A guest must never be forced to register to take a token or leave a review.
- No downloaded 3D model files; head and hair are three.js primitives.
- Nothing is fetched from the internet at run time: the face model and wasm are served from `public/mediapipe/`.
- Camera frames never leave the device.
- Alert window is exactly 15 minutes (`NOTIFY_WINDOW_MIN = 15`).
- Every API error is JSON `{ "error": "<message>" }` with a 4xx status; no request may produce a 500 from bad input.
- Whole test suite: `npm test` (runs `vitest run`).
- Commit messages end with `Co-Authored-By: Claude Fable 5.2 <noreply@anthropic.com>`.

## Review Focus

1. Malformed JSON body on any POST → 400 JSON error, not a 500 or an HTML page. (Test in Task 1.)
2. A waiting token left over from yesterday → ignored: the user has no active token today and can take a new one; numbering restarts at 1. (Test in Task 3.)
3. Staff "call next" with an empty queue → 200 with `serving: null`, no error. (Test in Task 3.)
4. Notification permission denied or unsupported → the in-app banner still appears and nothing throws. (Test in Task 7.)
5. Review comment containing HTML such as `<script>` → stored and shown as plain text. (Test in Task 8.)
6. Camera permission denied, no camera, or an insecure (non-HTTPS) page → a plain message and a link to the 3D preview, no crash; the camera is switched off when the user leaves the screen. (Test in Task 9.)

Schema (all five tables are created here so later tasks only add routes):

```sql
CREATE TABLE IF NOT EXISTS users(id INTEGER PRIMARY KEY, name TEXT NOT NULL, phone TEXT UNIQUE, password_hash TEXT, is_guest INTEGER NOT NULL DEFAULT 0, created_at TEXT NOT NULL);
CREATE TABLE IF NOT EXISTS sessions(token TEXT PRIMARY KEY, user_id INTEGER NOT NULL REFERENCES users(id));
CREATE TABLE IF NOT EXISTS services(id INTEGER PRIMARY KEY, name TEXT NOT NULL, category TEXT NOT NULL, price INTEGER NOT NULL, duration_min INTEGER NOT NULL);
CREATE TABLE IF NOT EXISTS tokens(id INTEGER PRIMARY KEY, day TEXT NOT NULL, number INTEGER NOT NULL, user_id INTEGER NOT NULL REFERENCES users(id), service_id INTEGER NOT NULL REFERENCES services(id), hairstyle_key TEXT, status TEXT NOT NULL, created_at TEXT NOT NULL, started_at TEXT, UNIQUE(day, number));
CREATE TABLE IF NOT EXISTS reviews(id INTEGER PRIMARY KEY, rating INTEGER NOT NULL, comment TEXT NOT NULL DEFAULT '', name TEXT NOT NULL DEFAULT '', created_at TEXT NOT NULL);
```

### Task 2: Accounts and guest mode

**Files:**
- Create: `server/auth.ts`; Modify: `server/app.ts` (mount router)
- Test: `server/auth.test.ts`

**Interfaces:**
- Consumes: `createApp`, `openDb`, `HttpError`.
- Produces:
  - `authRouter(db: DatabaseSync): Router` mounted at `/api/auth`.
  - `requireUser(db: DatabaseSync): RequestHandler` — reads `Authorization: Bearer <token>`, sets `res.locals.user: User`, else throws `HttpError(401)`.
  - `User = { id: number; name: string; phone: string | null; isGuest: boolean }`
  - `POST /api/auth/register { name, phone, password }` → `201 { token, user }`. 400 when name (trimmed) is not 1–40 chars, phone does not match `/^\+?\d{7,15}$/`, or password is shorter than 6. 409 when the phone is taken.
  - `POST /api/auth/login { phone, password }` → `200 { token, user }`; 401 on unknown phone or wrong password (same message for both).
  - `POST /api/auth/guest { name }` → `201 { token, user }` with `isGuest: true`, `phone: null`; 400 on bad name.
  - `GET /api/auth/me` → `200 { user }`; 401 without a valid token.
- Passwords: `crypto.scryptSync` with a 16-byte random salt, stored as `salt:hash` hex, compared with `timingSafeEqual`. Session token: `randomBytes(32).toString('hex')`.

### Task 3: Queue tokens, wait estimate, staff controls

**Files:**
- Create: `server/queue.ts`, `server/tokens.ts`; Modify: `server/app.ts`
- Test: `server/queue.test.ts`, `server/tokens.test.ts`

**Interfaces:**
- Consumes: `requireUser`, `HttpError`, `opts.now`, `opts.staffPin`.
- Produces:
  - `NOTIFY_WINDOW_MIN = 15`
  - `estimateWaitMinutes(ahead: AheadToken[], now: Date): number`, `AheadToken = { status: 'waiting' | 'serving'; durationMin: number; startedAt: string | null }`. Waiting adds `durationMin`; serving adds `Math.max(0, Math.ceil(durationMin - elapsedMinutes))`.
  - `isWithinNotifyWindow(status: string, etaMinutes: number): boolean` — `status === 'waiting' && etaMinutes <= 15`.
  - `dayKey(d: Date): string` — local `YYYY-MM-DD`.
  - `TokenView = { number: number; status: 'waiting' | 'serving' | 'done' | 'cancelled'; serviceName: string; hairstyleKey: string | null; aheadCount: number; etaMinutes: number; notifySoon: boolean }`
  - `POST /api/tokens { serviceId, hairstyleKey? }` (auth) → `201 { token: TokenView }`. 400 unknown `serviceId` or `hairstyleKey` not a string of 1–30 chars when present; 409 when the user already has a waiting or serving token **today**. Number = today's max + 1, starting at 1.
  - `GET /api/tokens/mine` (auth) → `200 { token: TokenView | null }` — today's waiting/serving token only.
  - `DELETE /api/tokens/mine` (auth) → `200 { ok: true }` (status → cancelled); 404 when there is none.
  - `GET /api/queue` → `200 { serving: number | null; waitingCount: number }` (today).
  - Staff, header `x-staff-pin` must equal `opts.staffPin` else 401:
    - `GET /api/staff/queue` → `200 { tokens: StaffToken[] }`, today's waiting+serving ordered by number; `StaffToken = { number; status; customerName; serviceName; hairstyleKey }`.
    - `POST /api/staff/next` → marks the serving token done, moves the lowest-numbered waiting token to serving with `started_at = now`, returns `200 { serving: StaffToken | null }`.
- "Ahead" of a token = today's tokens with a lower number and status waiting or serving.
